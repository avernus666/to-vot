# AVERNA ALPHA

### Alpha-версия Telegram-магазина и рабочего пространства для бизнеса

AVERNA объединяет две стороны одного продукта в Telegram:

- **Покупатель:** открывает каталог, добавляет товары в корзину, оставляет контакты и оформляет заказ.
- **Владелец бизнеса:** создаёт бизнес-пространство, добавляет товары, просматривает каталог и последние заказы.

Точка входа — обычный Telegram-бот. Кнопка в сообщении `/start` открывает Telegram Mini App. Внутри Mini App пользователь переключается между магазином и управлением бизнесом.

> Это alpha-версия, а не готовый платёжный SaaS. Онлайн-оплата, доставка, возвраты, Telegram-авторизация через `initData`, редактирование товаров, склад и полноценная CRM пока не реализованы.

## Стек

- Go — HTTP API, Telegram webhook, бизнес-логика.
- React + TypeScript + Vite — Telegram Mini App.
- PostgreSQL — пользователи, организации, товары, клиенты и заказы.
- Redis — инфраструктурная основа для фоновых задач (очереди пока не подключены к пользовательским сценариям).
- Rust — отдельный задел для аналитики.
- Docker Compose — локальная инфраструктура и запуск приложения.

## Что уже реализовано

### Telegram
- `POST /telegram/webhook` принимает Telegram updates.
- Проверяется заголовок `X-Telegram-Bot-Api-Secret-Token`.
- `/start` и `/catalog` отправляют приветствие с кнопкой открытия Mini App.
- URL Mini App задаётся через `MINI_APP_URL`.

### Покупки
- Публичный каталог магазина: `GET /v1/store/{slug}/products`.
- Корзина на стороне Mini App.
- Оформление заказа: `POST /v1/store/{slug}/orders`.
- Сервер повторно проверяет наличие и цену каждого товара, сам рассчитывает итоговую сумму.
- Заказ, покупатель и позиции сохраняются транзакционно в PostgreSQL.
- Поддерживается заголовок `Idempotency-Key`.

### Управление бизнесом
- Регистрация владельца с созданием организации.
- Вход по email и паролю.
- Создание и просмотр товаров; API поддерживает обновление карточки товара.
- Публикация и скрытие товаров из публичной витрины через интерфейс владельца.
- Просмотр последних заказов и базовой сводки.
- Управление статусами заказов: принять, завершить или отменить с проверкой допустимых переходов.
- Проверка членства и роли пользователя для доступа к данным организации.

## Быстрый запуск API и инфраструктуры

Требуются Docker Compose, Go 1.23+ и Make.

```bash
cp .env.example .env
docker compose up -d postgres redis
make migrate-up
make api
```

В другом терминале запусти Mini App:

```bash
cp apps/miniapp/.env.example apps/miniapp/.env
# В apps/miniapp/.env укажи VITE_API_BASE_URL=http://localhost:8080
make miniapp-dev
```

Vite покажет адрес приложения, обычно `http://localhost:5173`. API по умолчанию работает на `http://localhost:8080`; для локального запуска Mini App создай `apps/miniapp/.env`:

```env
VITE_API_BASE_URL=http://localhost:8080
```

## Запуск через Docker Compose

В `.env` укажи публичный HTTPS-адрес Mini App и Telegram credentials, затем выполни миграции и запусти профиль приложения:

```bash
docker compose up -d postgres redis
docker compose --profile tools run --rm migrate
docker compose --profile app up --build -d
```

Mini App будет доступен через порт `8088`. Nginx раздаёт frontend и проксирует `/v1/`, `/telegram/` и `/health/` в Go API.

## Подключение Telegram-бота

1. Создай бота через официальный `@BotFather` и скопируй токен.
2. Укажи в `.env`:

```env
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_WEBHOOK_SECRET=длинная_случайная_строка_из_букв_цифр_и_-_
MINI_APP_URL=https://твой-домен.example/?store=slug-магазина
```

3. Разверни приложение на публичном HTTPS-домене.
4. Установи webhook (подставь токен и секрет):

```bash
set -a; . ./.env; set +a

curl -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
  -H "Content-Type: application/json" \
  -d "{\"url\":\"https://твой-домен.example/telegram/webhook\",\"secret_token\":\"$TELEGRAM_WEBHOOK_SECRET\",\"allowed_updates\":[\"message\"]}"
```

5. Открой бота и отправь `/start`. Для перехода в конкретный магазин используй deep link `https://t.me/ИМЯ_БОТА?start=slug-магазина` — бот откроет Mini App с нужным каталогом.

Telegram требует HTTPS для Mini Apps. Не публикуй токен бота, пароли, `.env` или webhook secret в GitHub.

## API

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/v1/auth/register` | Создать аккаунт и организацию |
| POST | `/v1/auth/login` | Войти владельцу |
| GET | `/v1/organizations` | Список организаций пользователя |
| GET | `/v1/store/{slug}/products` | Публичный каталог |
| POST | `/v1/store/{slug}/orders` | Оформить заказ |
| GET | `/v1/organizations/{id}/products` | Товары организации |
| POST | `/v1/organizations/{id}/products` | Добавить товар |
| GET | `/v1/organizations/{id}/orders` | Последние заказы организации |
| POST | `/telegram/webhook` | Telegram webhook |

Все цены хранятся в минимальных денежных единицах (например, центах). Клиентская часть не является источником истины для цены заказа.

## Проверки

```bash
cd apps/api && go test ./... && go vet ./...
cd apps/miniapp && npm install && npm run build
```

Проверяй миграции на отдельной тестовой базе перед использованием с реальными данными. В этой среде зависимости Go/npm могут быть недоступны для загрузки, поэтому успешная сборка не заявляется без фактического запуска проверок.

## Что ещё нужно до реального запуска магазина

- Telegram `initData` validation и безопасное связывание Telegram-пользователя с аккаунтом.
- Редактирование/архивирование товаров, изображения и остатки.
- Уведомления владельцу и покупателю через Telegram-бота.
- Интеграция платежей и возвратов через подходящего провайдера.
- Настройка доставки, налогов, чеков и правил возврата под страну работы магазина.
- Rate limiting, защита от злоупотреблений, резервные копии, мониторинг и аудит безопасности.
- Политика конфиденциальности, сроки хранения и удаление персональных данных.

Не принимай реальные платежи и не загружай реальные данные клиентов, пока эти части не проверены и не настроены.
